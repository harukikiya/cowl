# ADR-0002: L1フロントエンドに tree-sitter を採用

日付: 2026-07-17 / 状態: 採択

## 決定
初期フロントエンドは tree-sitter-c による構文近似（L1）とする。
libclang（L2）は W5 で追加し、L1 は撤去せず併存させる。

## 理由
- 依存が軽くビルドが速い（libclang のリンク問題を初期に抱えない）
- エラー耐性: コンパイル不能な断片・編集中バッファでも動く
  （VSCode拡張で保存前解析をするための実質的な要件）
- 割り切り（制御フロー・スコープ・マクロ非対応）は unknowns と
  曖昧度指標で明示する設計にしたため、精度の低さが嘘にならない

## 却下案
- 最初から libclang: 精度は高いが、環境構築が重く、
  編集中バッファへの耐性が低い。L2として後段で採る
- 自前パーサ: 論外（保守コスト）
